## Actual storage and recovery

Production path `Saved/Settings/RomanPlayerPreferences.json`; file adapter rejects paths escaping project Saved, including traversal. Startup is readonly; malformed/unknown/oversized/unreadable files retain original bytes and report failure, with validated `.previous` fallback where available; missing current can recover previous. Explicit valid user apply alone writes.

Writes stage unique owned temporary UTF8 bytes, read back and validate exact values before promotion. Engine-source inspection showed generic IFileManager::Move deletes its destination before attempting the move: retired that writer before user-facing integration. Platform moves now retain valid current as `.previous` and attempt rollback on failed promotion; failed rollback leaves recovery bytes. A corrupt current moves to `.rejected`, never destroys an existing valid `.previous`. This is recoverable preferences storage, NOT a guarantee of transactional power-loss durability or a replacement for campaign saves. Cleanup removes only the exact owned temporary file, never directories/user collections. No Windows security/read-only settings changes.
